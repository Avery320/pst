# 重構 Code review

日期：2026-10-21。範圍為本次純網頁 PoC 重構及其日期、拖曳、繪圖、保存與排版演算法，以刪除維護責任為主要目標。

## 發現與修正

| 發現 | 影響 | 修正 |
| --- | --- | --- |
| 自訂月曆重做原生日期輸入已有的功能 | 多維護 375 行控制器、29 行 CSS，以及日期格、定位、焦點和鍵盤導覽 | 直接使用既有 `input[type="date"]`，刪除自訂元件、月曆格演算法及專用測試。 |
| 側欄另外快取文件及選取項目 | 復原／重做後先重設標記表單時，可能讀到上一份文件的顯示開始日期 | 移除側欄文件快取，每次透過控制器 getter 讀取目前文件。側欄只保留正在編輯的標記 ID。 |
| 圖表的日期、名稱、說明分成三種編輯回呼 | 重複轉送同一個項目更新流程 | 合併為 `onEdit(id, changes)`，直接接控制器的 `updateItem`。 |
| 一般編輯與整份文件替換各自包裝提交／錯誤處理 | 同一個寫入流程分成兩層函式 | 統一經 `editDocument` 驗證、記錄歷史、重繪與保存。 |
| 選取與重繪重複刷新拖曳圖層 | 同一個選取事件經圖表及控制器各刷新一次 | 選取由控制器統一寫回；重繪完成後刷新一次。 |
| pointerup 複製 pointermove 的位移更新 | 移動門檻與最後落點計算可能各自修改而不一致 | 放開時重用 pointermove 更新，再提交一次結果。 |
| 側欄與拖曳圖層重複建立元素／按鈕 | 類別、ARIA 及按鈕型態容易不一致 | 使用既有 `createElement`／`createButton`，不增加元件框架。 |
| 所有表頭格都計算 ISO 週 | 年、月及日表頭也做不需要的日期運算 | 只有週一開始的週表頭才計算 ISO 週。 |

應用 TypeScript／CSS：3,149 → 2,642 行，減少 507 行（16.1%）；檔案數 23 → 21。這是相對本輪 review 開始時的工作目錄計算，不包含測試、文件、HTML、套件或既有 Rust 刪除量。

## 保留的最小實作

- 日期：UTC 整天運算；月份末日夾限、ISO 週、週首範圍及完整週乘 5 的平日計數。
- 拖曳：從按下時的原資料計算位移，對稱四捨五入，最後夾限。預覽不修改文件，放開只提交一次。
- 排版：四個固定欄位依可縮空間線性縮小；日寬取文件設定與容器平均日寬的較大值。
- 繪圖：日期、項目、標記各線性掃描。HTML、SVG、拖曳與 PNG 共用尺寸，沒有第三方繪圖內部狀態。
- 歷史：最多 50 個完整快照，序列化比較是否變更；保存及 JSON 匯入使用同一份文件驗證。

沒有新增排程引擎、通用表單引擎、狀態框架、虛擬列表、碰撞避讓或另一份演算法實作。JSON 舊欄位相容處理留在輸入邊界，沒有保留舊圖表底座。

## 驗證與限制

63 個 Node.js 測試，另執行嚴格 TypeScript、正式建置、函式實際引用、CSS／DOM 引用及 SVG XML 檢查。函式掃描排除僅有型別或測試引用的情況，檢查範圍未發現未使用的生產函式。

原生日期選擇器的呈現、鍵盤操作與月曆週首由瀏覽器及語系決定；圖面的週首設定繼續控制時間軸與「本週」範圍。依使用者要求，本輪沒有操作或擷取使用者已開啟的網頁，瀏覽器指標互動及跨瀏覽器外觀不在已完成的自動驗證內。

發布使用保留既有 Git 歷史的一般提交及推送。GitHub Pages 由 `main` 的 Actions 工作流程建置與部署，部署結果另外以該次提交的 workflow 與公開資產核對。
